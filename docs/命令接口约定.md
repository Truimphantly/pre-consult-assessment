# 命令接口约定

> 本文件是命令行与计分结果的**接口契约**。改 CLI 或改 `ScoreResult` 字段前，先改本文件，再改代码。
> 所有命令均在仓库根目录执行（PowerShell），统一使用 `python -m app.cli ...`。

## 1. 命令总览

| 命令 | 作用 | 退出码 |
| --- | --- | --- |
| `self-check` | 冒烟：打印版本、已实现量表、可用命令 | 0 |
| `list-scales` | 列出已实现量表（编码/名称/条目数/分值区间/分级） | 0 |
| `rule-check` | 扫描硬性规则 R1～R8 | 0 通过；1 有违规 |
| `score --scale <编码> (--answers <文件> \| --demo)` | 计分并输出 JSON 结果 | 0 成功；1 输入或业务错误 |
| `report --scale <编码> (--answers <文件> \| --demo)` | 计分并输出中文报告片段 | 0 成功；1 输入或业务错误 |
| `verify` | 规则扫描 + 全部单元测试，一键验收 | 0 通过；1 未通过 |

退出码含义：

- `0`：命令成功完成。
- `1`：业务或输入错误（`ScoreError` / `InputError`），错误信息为中文，指向具体条目或参数。
- `2`：命令用法错误（未知命令、缺少必需参数），由 `argparse` 产生。

## 2. 答案文件格式

`--answers` 接受 UTF-8 JSON 文件：

```json
{
  "scale_code": "adl",
  "answers": [
    {"item_code": "adl_eat", "option_code": "full"},
    {"item_code": "adl_bath", "option_code": "full"}
  ]
}
```

规则：

1. `scale_code` 必须与 `--scale` 一致，不一致按输入错误处理。
2. 每个 `item_code` 在本次提交中只能出现一次，重复即报错。
3. 必填条目缺失时整体报错，并在 message 中列出缺失条目编码；不得以 0 分补齐。
4. 未知 `item_code` / `option_code` 一律报错，不做静默忽略。

## 3. `score` 输出格式

标准输出为一段 UTF-8 JSON（便于被其他程序消费）：

```json
{
  "scale_code": "adl",
  "scale_name": "日常生活活动能力评定量表（Barthel 指数）",
  "standard_ref": "WS/T 888—2026 附录B 表B.1",
  "total": 85,
  "max_total": 100,
  "item_scores": {"adl_eat": 10, "adl_bath": 5},
  "item_labels": {"adl_eat": "独立进食", "adl_bath": "独立完成"},
  "level_label": "轻度依赖",
  "advice": "存在轻度依赖……",
  "missing": []
}
```

字段含义：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `total` | int | 总分（各项得分之和） |
| `max_total` | int | 该量表满分 |
| `item_scores` | object | 条目编码 → 得分 |
| `item_labels` | object | 条目编码 → 所选选项的中文标签 |
| `level_label` | string | 分级名称，来自 `app/scales.py` 的 `levels` |
| `advice` | string | 分级对应的中文建议 |
| `missing` | array | 缺失条目编码；成功时为空数组 |

## 4. `report` 输出格式

标准输出为中文纯文本，固定包含四段：

1. 标题与元信息（量表名、标准来源、评估时间、对象）。
2. 总分与分级（含结论说明）。
3. 分项得分（条目序号、名称、得分、选项标签）。
4. 合规说明（固定尾注：不作诊断依据，请医师确认）。

## 5. `verify` 输出格式

```
[规则扫描] R1 计分返回类型 ......... 通过
...
[单元测试] 运行 12 项，失败 0 项
验收结果：通过
```

失败时最后一行必须是 `验收结果：失败`，并以退出码 1 结束。
