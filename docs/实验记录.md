# AI 编码实验记录（AGENT.md 驱动的最小功能落地）

> 对应作业第 3 部分：从修订后的 `AGENT.md` 出发，用 AI 编码工具完成一个最小、可独立验证的功能，
> 并记录"投喂—生成—验证—违规—修订"的完整过程。
> 实验时间：2026-10　实验环境：Windows 11 + PowerShell、Python 3.12.14、仓库 `pre-consult-assessment@main`

## 1. 步骤一：选一个最小、可独立验证的功能

| 候选功能 | 依赖 | 可验证性 | 结论 |
| --- | --- | --- | --- |
| 健康检查接口 | 需要 Web 框架（本项目零依赖） | 中：需起服务、造端口 | 不选 |
| 列表查询页面 | 需要前端工程 | 低：一期没有前端 | 不选 |
| 登录表单校验 | 需要账号与会话体系 | 中：先造一套假账号 | 不选 |
| **ADL 量表计分 + 报告片段** | 仅标准库 | 高：输入固定则输出可断言，退出码可判定 | **选中** |

选择理由：ADL 计分是"21 张量表 → 报告"这条主链路的纵向切片，改一处就能看到端到端效果；
输入是少量结构化答案，输出是确定性的总分、分级与文本，适合用单元测试与命令退出码双重验证；
且不需要数据库、不需要网络、不需要前端，符合"最小"要求。

## 2. 步骤二：在发出第一条编码指令前，先把 AGENT.md 交给 AI

做法（可复现）：

1. 仓库根目录放 `AGENT.md`，并在提示词中显式要求"先读 AGENT.md，再动手"。
2. 使用 AGENT.md 第 11 节的提示词模板，把范围、约束、完成标准一次讲清。
3. 要求 AI 在动手前先复述它读到的硬性规则（用于确认它真的加载了文件，而不是凭印象写代码）。

实际使用的提示词：

```text
你是本仓库的编码助手。开始前请先阅读仓库根目录 AGENT.md，并严格遵守其中的硬性规则（第 6 节）
与禁止清单（第 7 节）。

任务：实现 ADL（Barthel 指数）量表的最小闭环——结构化题库、计分、分级与中文报告片段，
并接入命令行 score / report / verify 子命令。
范围：只改 app/ 与 tests/ 下的相关文件，不改其他模块。
约束：
1) 不得引入第三方依赖；只改标准库用法。
2) 计分函数必须返回 ScoreResult；错误一律 raise ScoreError("中文原因")。
3) 阈值只能写在 app/scales.py，禁止写进 engine.py / report.py。
4) 先补 tests/ 用例，再改实现。
完成标准：python -m app.cli verify 退出码为 0，并把关键输出贴给我。
如果我的要求与 AGENT.md 冲突，请先指出冲突点，不要默默照做。
```

AI 复述的关键约束（确认已加载）：返回 `ScoreResult`、统一 `ScoreError`、阈值只在 `scales.py`、
只用标准库、`verify` 必须绿。

## 3. 步骤三：生成代码，并用 AGENT.md 里写明的验证命令验证

### 3.3 修复动作

1. 计分改为返回 `ScoreResult`；缺项改为 `raise ScoreError("缺少必填条目：…")`；
2. 未知量表/条目/选项、重复作答统一改为 `ScoreError`（中文提示，含编码与可用选项）；
3. 分级阈值全部搬回 `app/scales.py` 的 `levels`，`engine.py` 只做区间匹配；
4. 英文 `print` 改为中文异常提示，CLI 统一由 `main()` 映射退出码；
5. 补齐 `load_answers` 的结构校验（`InputError`）。

## 4. 步骤四：违规记录与 AGENT.md（或提示词）的修订

### 4.1 违规清单

| 序号 | 违反的规则 | 具体表现 | 为什么会犯 | 修订动作 |
| --- | --- | --- | --- | --- |
| 1 | R1 计分返回类型 | 缺项时 `return None`；正常路径返回 `dict` | 原文只写"必须返回 ScoreResult"，没给反例，AI 按最省事的方式写 | AGENT.md 第 6 节补"反例/正例"两列；提示词模板明确写"禁止返回 None/dict" |
| 2 | R2 统一异常 | `raise ValueError("bad option")` | "业务错误统一抛 ScoreError"被理解为风格建议，缺少"禁止用内置异常"的强表述 | 规则改为"禁止 ValueError/KeyError/assert 做业务校验"，并给出正例 |
| 3 | R3 中文输出 | `print("missing answer: " + item.code)` | 规则说了"面向人的文本必须中文"，但没说要覆盖异常路径 | 第 6 节 R3 补反例；**同时发现自检器漏检字符串拼接**，检查器改为遍历参数子树 |
| 4 | R4 阈值集中 | `if total >= 60: level = "轻度依赖"` | 只写"只能写在 scales.py"，没说明"引擎里出现数字常量即违规" | 规则补"不得出现两位以上数字常量"与检查方式；正例给出 `pick_level()` 写法 |
| 5 | 环境（编码） | 用 PowerShell `Set-Content -Encoding UTF8` 改写 `cli.py`，文件带 BOM，`ast.parse` 报 `invalid non-printable character U+FEFF` | AGENT.md 只写了"UTF-8"，没提醒 Windows 工具会写 BOM | 第 8 节"坑表"补充 BOM 条目与正确落盘方式 |

### 4.2 修订前后对比（以 R1 为例）

修订前（v0.1.0）：

```text
| R1 | 计分相关函数必须返回 ScoreResult，不得返回 None、裸数字或 dict | 扫描 engine.py、report.py 中的 return None |
```

修订后（v0.2.0）：

```text
| R1 | 计分相关函数必须返回 ScoreResult，不得返回 None、裸数字或 dict
     | 反例：def score(...): ... return None
     | 正例：return ScoreResult(scale_code=..., total=85, ...)
     | 检查方式：扫描 engine.py、report.py 中的 return None |
```

差异不只在"多两列"：修订后 AI 能直接对照"我这样写算不算反例"，而不用先理解抽象要求。

### 4.3 修订效果

按修订后的 AGENT.md（v0.2.0）与提示词重新生成同一功能，规则扫描一次通过（8/8），
45 项测试一次通过；第二次实现中没有再出现返回 `dict`、内置异常或硬编码阈值。

## 5. 结论：AGENT.md 怎么写才真的管用

1. **能自动判定的规则才有约束力**：把"注意异常处理"换成"禁止 `raise ValueError`，扫描 `app/` 下所有文件"，
   违规才会在提交前暴露。
2. **给出反例比给出原则更有效**：AI 不会主动推断"返回 dict 算不算违反返回类型"，但会照抄反例的形状。
3. **规则要覆盖异常路径**：首版在正常路径上写得像模像样，问题全在缺项、未知编码这些分支。
4. **验证命令必须一条可跑**：`python -m app.cli verify` 同时给出规则结论与测试结论，退出码即验收标准。
5. **违规后先问"文档缺了什么"**：只改代码，下一次换个 AI 还是会犯；补上反例与检查器，问题才会消失。
